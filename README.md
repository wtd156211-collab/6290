# bytestream UTF-8 增量解码（从 0 实现）

本仓库是起始环境：只有规格、样例和现场记录，没有实现代码。

## 1. 范围

要做的事：在仓库根目录新写入口脚本 `stream_decode.py`（Python 3.13，仅标准库、无第三方依赖、无构建步骤），对按块给出的字节流做增量式 UTF-8 解码，输出逐字符结果与非法位置清单。

不做的事：

- 只处理 UTF-8；不识别 BOM，`EF BB BF` 按普通字符 U+FEFF 输出。
- 不做 Unicode 规范化、不判定字形宽度、不做转义；字符按码点原样输出。
- 不联网、不读环境变量、不依赖系统区域设置。
- 不做猜测修复：非法字节不得用 `?`、`□` 或其他字符顶替。

## 2. 口径与公式

### 2.1 字节流与偏移

块目录里的 `chunk-NNN.bin` 按文件名字典序读取并拼接：`S = c0 ++ c1 ++ ... ++ c(K-1)`，`N = |S| = Σ|ci|`。块边界不携带语义，块允许为 0 字节，一条序列可以被切在任意位置（每块只装 1 个字节也算合法）。**同一字节流的任意切分必须得到完全相同的输出。**

偏移以下标给出，基准是 S 的起点、从 0 开始、左闭右开 `[s, e)`，单位是字节而不是字符。

### 2.2 合法性判定（严格 UTF-8）

| 长度 | 首字节 | 各位允许范围（按位置顺序） |
| --- | --- | --- |
| 1 | `00–7F` | —— |
| 2 | `C2–DF` | `80–BF` |
| 3 | `E0` | `A0–BF`，`80–BF` |
| 3 | `E1–EC`、`EE–EF` | `80–BF`，`80–BF` |
| 3 | `ED` | `80–9F`，`80–BF` |
| 4 | `F0` | `90–BF`，`80–BF`，`80–BF` |
| 4 | `F1–F3` | `80–BF`，`80–BF`，`80–BF` |
| 4 | `F4` | `80–8F`，`80–BF`，`80–BF` |

不允许过长编码、代理区、超出 U+10FFFF。`80–BF` 是续字节，`C0`、`C1` 与 `F5–FF` 不能作为起始字节。

码点还原公式：

    2 字节：cp = ((b0 & 1F) << 6)  | (b1 & 3F)
    3 字节：cp = ((b0 & 0F) << 12) | ((b1 & 3F) << 6) | (b2 & 3F)
    4 字节：cp = ((b0 & 07) << 18) | ((b1 & 3F) << 12) | ((b2 & 3F) << 6) | (b3 & 3F)

### 2.3 非法序列：替换并记录

一条非法序列只产生一个替换字符 `U+FFFD`，其 `span` 覆盖「能作为合法序列前缀的最长字节串」（最长合法前缀）；紧随其后的字节重新按起始字节判定，可能又是替换字符，也可能是正常字符。

原因码三种：`invalid_lead`（期望起始字节的位置出现 `80–C1` 或 `F5–FF`）、`invalid_continuation`（续字节不在当前位置的允许范围内，涵盖过长编码、代理区、越界和被 ASCII 字节打断的序列）、`truncated_at_eof`（流已结束仍有未完成的序列）。

### 2.4 覆盖不变式

- 所有输出的 `span` 按起点严格递增、互不重叠，并集恰好是 `[0, N)`：每个字节恰好属于一条记录。
- `decoded.jsonl` 中 `complete=false` 的记录与 `illegal.jsonl` 的记录个数相同、顺序一致、`span` 相同。

## 3. 状态机

    空闲            —— 等待起始字节
    待续(n, i, s)   —— 序列总长 n∈{2,3,4}，已收 i 个字节（1≤i<n），起始偏移 s

1. 空闲 + 起始字节：长度为 1 时直接输出字符（`complete=true`）；否则进入 `待续(n,1,s)`。
2. `待续` + 字节落在第 i+1 位的允许范围：收下；`i+1 == n` 时按 2.2 还原码点、输出字符、回到空闲。
3. `待续` + 字节越界：输出 `U+FFFD`，`span = [s, s+i)`，原因 `invalid_continuation`；回到空闲，并用当前字节重新执行第 1 步。
4. 空闲 + 非起始字节：输出 `U+FFFD`，`span` 长度 1，原因 `invalid_lead`。
5. 流结束仍在 `待续`：输出 `U+FFFD`，`span` 为已收的 i 个字节，原因 `truncated_at_eof`。

状态最多保留 3 个待续字节，已处理的内容不需缓存；块与块之间只延续这份状态。

## 4. 输入输出与文件格式

调用方式：`python stream_decode.py <块目录> <输出目录>`。块目录内是 `chunk-NNN.bin`（编号十进制、补零到同一宽度，样例 3 位），按文件名字典序读取，不递归子目录。

在 `<输出目录>` 下写两个文件（目录不存在则创建，同名旧文件覆盖）：

- `decoded.jsonl`：每行一条字符记录，字段固定为 `char`、`span`、`complete`。
- `illegal.jsonl`：每行一条非法位置记录，字段固定为 `span`、`reason`。

样例 `07-log-scene-mixed` 的两行：

    {"char":"中","span":[9,12],"complete":true}
    {"span":[16,17],"reason":"invalid_lead"}

约定：

- 两个文件都按流顺序（`span` 起点升序）排列；没有非法序列时 `illegal.jsonl` 为 0 字节空文件。
- `complete=true` 当且仅当字符来自完整合法序列；流中真实出现的合法 `EF BF BD`（U+FFFD）是 `true`，与替换产生的 `false` 区分。
- 编码 UTF-8、行尾 LF、末行以换行结束；每行一个 JSON 对象，非 ASCII 字符按原文写出，控制字符按 JSON 规则转义。
- stdout、stderr 内容不限。退出码 0 表示整条流处理完毕（出现非法序列也算 0），非 0 只用于参数或 IO 错误。

## 5. 性能与验收口径

预算（Python 3.13、单核、本机 WSL 环境测量）：

- 吞吐：16 MiB 输入、4 KiB 分块，端到端（含读块与写输出）≥ 1 MiB/s。
- 内存：峰值常驻增量 ≤ 8 MiB 且不随流长度增长；不得把整条流或全部块拼接成一个 `bytes`。
- 不得把「字节到字符」的判定交给现成解码设施（`bytes.decode`、`str(..., encoding=...)`、`codecs`、`io.TextIOWrapper` 等），判定逻辑从 0 写起；用 `json` 序列化输出行可以。

验收：

1. 逐用例运行 `samples/chunks/<用例>`，把生成的 `decoded.jsonl`、`illegal.jsonl` 与 `samples/expected/<用例>.*` 按行解析后做字段级比较，行数与顺序也必须一致。
2. 分块无关性：验收方会用未公开的切分方式重切同一字节流，输出必须与公开期望逐行相同。`07-log-scene-mixed` 与 `08-same-stream-one-byte-chunks` 就是同一字节流的两套切分，两份期望内容完全相同。
3. 不得读取 `samples/expected/`，不得按目录名、文件数或长度写死结果。
4. 只用标准库；无第三方依赖、无构建步骤、无网络访问。

## 6. 样例说明

`samples/chunks/<用例>/chunk-NNN.bin` 与 `samples/expected/<用例>.decoded.jsonl`、`<用例>.illegal.jsonl` 一一对应：

| 用例 | 字节数 | 覆盖点 |
| --- | --- | --- |
| `01-ascii-with-empty-chunk` | 8 | 纯 ASCII；含 NUL、CR、LF 与 0 字节块 |
| `02-char-split-across-boundary` | 6 | 两个汉字各跨一次块边界（2+1、1+2 两种切法） |
| `03-byte-per-chunk-and-empty-chunk` | 9 | 4/3/2 字节序列拆到相邻块，含 0 字节块 |
| `04-illegal-top-level-bytes` | 9 | 孤立续字节 `80`、过长首字节 `C0` 与 `AF`、`F5`、`FF` |
| `05-truncated-at-eof` | 7 | 末尾未完成的多字节序列，以及被 ASCII 字节打断的序列 |
| `06-illegal-multibyte-forms` | 15 | 过长 `E0 80 80`、代理区 `ED A0 80`、越界 `F4 90 80 80`、`C1 BF`、被 `(` 打断的 `E2 81` |
| `07-log-scene-mixed` | 20 | 日志片段：汉字与 emoji、孤立 `80`、真实编码的 U+FFFD（`EF BF BD`），序列跨块 |
| `08-same-stream-one-byte-chunks` | 20 | 同 `07` 的字节流，改成每块 1 字节；期望文件与 `07` 逐字节相同 |

现场记录见 `samples/notes.md`。
